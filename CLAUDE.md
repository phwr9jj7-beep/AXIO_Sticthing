## Design grounding

Before writing or changing anything a person sees, read the **LabOnoM Design Guide** (private repository `LabOnoM/design`, pinned here as version `2026.10.0` in `DESIGN_VERSION`): `DESIGN.md` at this repository's root is its family file "AROS Deep Space", verified by `scripts/design-pin-check.sh`; the "Lab Canvas" profile, through the generated Qt palette `dist/lab-canvas.qss` (vendored here as `design/lab-canvas.qss`); the guide's `GLOSSARY.md` holds every word on screen in English and Japanese, `STATES.md` every state a surface can be in, and `CONFORMANCE.md` the measured tests this repository keeps green. Design the change with the `ux-foundations` skill's P1 brief, audit the result with P2 and P3 in both themes, and record findings as clauses with tests. Tokens come from the guide, never pasted hex; status hues are reserved; no state is colour alone; words come from the glossary; every string ships in English and Japanese.

For this PySide6 application the profile arrives as a Qt palette: `design/lab-canvas.qss`, generated by the guide
from the Lab Canvas tokens (dark theme, the profile's default). Adopting it in `scripts/gui_stitch.py` in place of
the hard-coded hex values is the next UI task for AXIO and needs a visual check on a display before it ships; until
then this file records the target, and `tests/test_design_pin.py` keeps the pinned guide honest.
